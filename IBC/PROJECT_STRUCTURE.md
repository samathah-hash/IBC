# Project Structure — IBC Playwright Test Suite

This document describes the current directory layout and purpose of each file in the IBC Playwright end-to-end test project.

## Root Directory

| File | Purpose |
|---|---|
| `package.json` | Node.js project manifest. Declares `@playwright/test` and `docx` as development dependencies. |
| `package-lock.json` | Locks the exact dependency versions installed for this project. |
| `playwright.config.ts` | Playwright configuration. Sets `tests/` as the test directory, a 5-minute global timeout, Microsoft Edge, screenshot capture, the Pactrak QA base URL, and reuses saved authentication state only when it matches the configured app origin. |
| `PROJECT_STRUCTURE.md` / `PROJECT_STRUCTURE.docx` | Project-structure references in Markdown and Word formats. |
| `_generate-doc.js` | Generates `PROJECT_STRUCTURE.docx` from the document content defined in this script. |

## `locators/`

Contains TypeScript `const` objects that centralise UI selectors and static test data.

| File | Contents |
|---|---|
| `bookingLocators.ts` | Selectors and values for the Bookings page, including page URL, controls, option lists, day-rate inputs, success messages, and booking ID matching. |
| `customerLocators.ts` | Selectors for the B2C login form and Customers page, including login controls, page URL, invite-customer controls, drawer and popover selectors, and confirmation message matching. |

## `pages/`

Contains shared page-object workflows used by the functional tests.

| File | Responsibility |
|---|---|
| `LoginPage.ts` | Handles B2C authentication using `LOGIN_USERNAME` and `LOGIN_PASSWORD`, waits up to 2 minutes for manual verification, and saves browser storage state to `playwright/.auth/user.json`. Skips login when no authentication redirect occurs and the browser remains on the configured app origin. |

## `tests/`

Contains the current Playwright test specifications.

### `tests/functional/`

| File | What it tests |
|---|---|
| `advancedsearch.spec.ts` | Logs in, opens the dashboard, and clicks the Advanced Search control. |
| `userlogin.spec.ts` | Verifies that a user can authenticate successfully and return to the configured app origin. |

## `playwright/`

Contains runtime authentication state managed by Playwright. The configuration reuses it only when its origin matches the configured app origin.

| Path | Purpose |
|---|---|
| `playwright/.auth/user.json` | Saved browser storage state captured after login. This file is generated at runtime, may contain sensitive session data, and should not be committed to source control. |

## `test-results/`

Generated by Playwright after test runs. It can contain per-test output such as screenshots and failure context. This directory is generated output and should be excluded from source control.

## Architecture Summary

```text
playwright.config.ts          ← Playwright configuration
locators/                     ← Selectors and static test data
pages/                        ← Shared page-object workflows (LoginPage)
tests/
  functional/                 ← Current feature-level test specifications
playwright/.auth/              ← Runtime: persisted authentication state
test-results/                 ← Runtime: screenshots and failure reports
```

The current functional test files are `advancedsearch.spec.ts` and `userlogin.spec.ts`. Both use `pages/LoginPage.ts` for authentication. The `locators/` directory contains booking and customer selector modules.
